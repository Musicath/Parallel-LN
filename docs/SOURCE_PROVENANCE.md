New research material is included only when it is relevant to an active manuscript result and its source can be identified. The license of this repository does **not** automatically clear copied code from other authors or dependencies.

Historical run-source SHA-256 values above are provenance identifiers, **not** evidence that a fresh run matches the paper. If a source file is modified for portability, record the original hash and explain the change in its experiment README.

The shipped compact CSVs are byte-identified by
[`DATA_MANIFEST.sha256`](DATA_MANIFEST.sha256), which is checked by the unit
test suite. These hashes detect silent changes to release data; they do not
authenticate the historical raw logs or replace the separate provenance
and numerical audits described above. The CSVs use LF line endings in the Git
repository and working tree, so the byte hashes are portable across a normal
checkout; the manifest test also rejects CRLF data files.

The read-only source-to-extraction comparison for the Helmholtz task,
network, optimization settings and protocol-specific reporting intervals is
documented in [`PINN_EXTRACTION_AUDIT.md`](PINN_EXTRACTION_AUDIT.md).

## Authorship and license review

The added experiments are a mixture of copied historical research scripts, modified extractions from private author-side frameworks, reconstructed standalone runners, and newly prepared data/figure utilities. Do **not** describe the collection as entirely newly written. The original `Musicath-base` Git history identifies the `musicath` account as the committer of its ViT/VGG files, but that fact alone does not establish authorship of every underlying implementation. The historical ViT code has distinctive structural and initializer overlap with the classic timm implementation; the extracted model carries a notice and `THIRD_PARTY_NOTICES.md` records the Apache-2.0 upstream attribution. This is a provenance record, not a legal determination of rights.

The author's permission to publish a minimal paper-specific extraction does not authorize publishing the entire private framework. The incomplete VGG figure provenance and pending PINN extraction validation below remain visible regardless of the publication decision.

The compact numerical CSVs and the fixed 6k label/index manifest are separate
release artifacts from the code. On 2026-10-10, the author explicitly approved
publishing all nine candidate CSVs under Apache-2.0. This records the chosen
data terms; it does not redistribute or relicense CIFAR-10 images or make an
independent legal determination about source ownership. The per-file classes,
privacy screening and fixed-label provenance are recorded in
[`DATA_RELEASE_REVIEW.md`](DATA_RELEASE_REVIEW.md).

## Exclusions and unresolved items

- The later PINN k=1/k=4 snapshots use a different protocol from the manuscript's historical Helmholtz table. They have deliberately not been copied into this repository as that table's reproduction code.
- The original `Norm-exp-base/PDE` `helmholtz_learnable_2` trainer, one-cell and full-matrix launchers, 42-cell W&B trace, and original run records have been located. Adam `3e-4` and SGD `1e-4` are the archived initial learning rates; the inspected training path does not advance its configured scheduler. Two 6,000-step PLN[4] re-runs with the original trainer matched the printed table values at widths 128 and 256. The public candidate contains a separate standalone extraction and sanitized data, **not** a copy of the broad private `extension` framework. Two selected 6,000-step cells of this extraction have since matched printed precision (one also matches the archived raw metric); the other 40 selected cells and full search remain unvalidated. The one-cell and full-matrix launcher SHA-256 digests are `41a1eea1dc280ee0af016be2178c10f5ef244ba8a85976daea0b445fb740e542` and `473fe5833f36440d4a321602358aebfe20c304130f914b1c445d8733593c4252`.
- All 42 W&B metadata records cite historical commit `94db456f699a83af71fb7afb12b5ebf5383a13ac`, but that commit lacks the `helmholtz_learnable_2` task. The exact then-running source state may have included uncommitted changes and cannot be certified by the archived Git hash. The NTK follow-up uses the different `helmholtz_new` protocol and is not a source of the manuscript Table II values.
- The public release contains a minimal extracted ViT model, not the broader `Musicath-base` framework. One full GPU configuration has now been compared with its archived best-fit value ([report](VIT_FULL_VALIDATION_20261010.md)); this does not verify the full grid. The historical 20k label artifact is not available for a bytewise comparison.
- A `Musicath-base` VGG backbone and older initialization scripts were found, but those older scripts sweep 108 ReLU/Tanh×No/LN/BN combinations rather than the manuscript's 945-run PLN[8]/ReLU/SiLU/Tanh/SAT grid. A more relevant private `soft-norm/experiments/VGG` snapshot on the eight-RTX-4090 host contains 630 launch scripts for the five paper activations, seven learning rates and nine initialization scales, but only seeds 20 and 30 (5×7×9×2). Its configured `results/A-log-results/ICML-2026-VGG` and `results/B-experiment-results/ICML-2026-VGG` directories were not present in that snapshot; the five scheduler output files inspected were empty, and a home-directory search found no matching per-run output logs. A minimal model and prospective one-cell runner are now extracted, but neither 945 completed runs nor the figure's numerical data have been verified. An archived earlier manuscript describes the figure metric as validation accuracy, while the relevant historical runner's `val_loader` calls `CIFAR10(..., train=False)` and records `test accuracy`; the numerical records still need tracing before resolving manuscript wording. Do not imply the figure can be reproduced until the exact sweep and numerical records are found or a clearly labeled new replication is completed.
- Translation/fairseq snapshots and unrelated experiments are excluded from the active paper release.

Before publishing changes to the public GitHub repository: verify authorship or permission for every added source file, scan the exact staged diff for credentials, private paths and large artifacts, validate the environment on a clean checkout, and review the README's status statements against actual test logs. This is a release gate, not a legal opinion.
